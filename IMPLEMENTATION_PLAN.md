## 2. Durable website-to-EPUB conversion engine — Partial

**Existing behavior to preserve:** `WebNovelExportService` is a direct `dataSync` foreground service with progress/cancel notification and `START_REDELIVER_INTENT`. `WebNovelEpubUtility` processes chapters sequentially, writes each completed XHTML and URL atomically into app-private checkpoints keyed by URL and scrape options, retries transient errors and 429 responses, parses both numeric and HTTP-date `Retry-After`, and persists per-host cooldowns. Repository import uses a stable URL/options-derived ID to avoid duplicate generated books.

**Implemented in this slice:** Room v6 stores a stable job ID, serialized scrape options and destination, status, progress, error, cooldown deadline, checkpoint key, result book ID, book title, and timestamps; Room v7 adds the discovery source registry through migration 6→7. Room v8 adds runner kind, durable automatic-run intent for jobs already started by the user, and a backup-restore transaction marker. Claims register a process-local runner token under the same repository lock as the Room claim; startup reconciles only tokens absent from the live-process registry. Conditional progress/finalization keeps stale claims from publishing. Queued jobs run sequentially through the existing direct foreground service. A regular WorkManager CoroutineWorker also runs due automatic jobs and deferred 429 retries without starting a foreground service. It shares the Room lease and EPUB/checkpoint utility, yields after a newly downloaded chapter in a short slice, preserves cached chapters, and reschedules its next slice. User pause/cancel clears automatic intent and cancels tagged WorkManager work; restore is rejected while a conversion owns a runner lease and restored jobs are kept inactive.

**Backup and restore:** The root backup remains version 2 and is unchanged. An optional version 1 `webNovel` extension carries custom Discover source definitions and configuration, built-in source enabled flags, cached source results, durable conversion jobs, validated manifests and downloaded chapter checkpoints, and persisted host cooldowns. Existing version 1 and version 2 backups without this extension remain accepted. Restore merges rows additively with existing device rows taking precedence; settings and recognized built-in enabled flags follow the existing `replaceExistingSettings` option. Restored jobs are inactive (`autoRun=false`). A checkpoint collision preserves the local files and leaves the restored job visibly failed until the user confirms a reset. Restore journal version 3 records a transaction ID matched against a Room marker persisted atomically with restored data, distinguishing a committed extension-only restore from rollback even when the backup contains no books; staged files remain until the journal is cleared.

The checkpoint directory holds a bounded, versioned chapter manifest with the resolved TOC origin, title, cover URL, and ordered selected chapter URLs/labels. Retries use that snapshot and do not refetch the TOC. A corrupt/mismatched manifest fails visibly; the manager offers a confirmed reset that removes only the manifest, preserves per-chapter files, resets saved progress, and refuses while another job can share the checkpoint. Cooldowns longer than 60 seconds are synchronously committed before a job is deferred. WorkManager remains subject to Android background scheduling and quota limits, so start times can be delayed by the OS; no exact alarm or background-started foreground service is used. Migration, recovery, and Worker tests passed in CI; actual Android service/Worker execution, process-death behavior, and OS quota behavior remain unverified on device.

## 6. Offline Calibre-style PDF-to-EPUB reflow — Proposed

**Goal and boundary:** Improve local PDF-to-EPUB conversion into a readable, chapter-based reflowable EPUB while keeping the current page-image conversion as the fidelity fallback. Build an independent Kotlin pipeline on the existing PDFBox Android, `PdfRenderer`, and ML Kit components; conversion remains offline. Do not port or share Calibre code or ship its CLI. Use a pinned Calibre `ebook-convert` 9.19.0 build only as a development comparison reference; record the binary hash and options with fixtures. Any decision to bundle or directly reuse Calibre requires a separate technical and licensing review. References: [PDF input plugin](https://github.com/kovidgoyal/calibre/blob/master/src/calibre/ebooks/conversion/plugins/pdf_input.py), [PDF reflow implementation](https://github.com/kovidgoyal/calibre/blob/master/src/calibre/ebooks/pdf/reflow.py), and [ebook-convert options](https://manual.calibre-ebook.com/generated/en/ebook-convert.html). Pin a Calibre release because the source `master` URLs move.

**Current baseline:** `PdfEpubConverter.kt` currently extracts positioned text and OCRs pages with fewer than 35 extracted characters, sorts lines by y/x, guesses paragraphs and headings, and emits an XHTML section per nonempty PDF page. Its separate Images mode renders each page to JPEG. The operation runs in a ViewModel coroutine, reports page progress, and imports the completed cache EPUB through `BookRepository`; it has no durable job or recovery state. There are no PDF-conversion fixtures or automated tests yet.

**Proposed contracts and pipeline:** Refactor extraction and packaging behind testable stages with explicit records for document metadata/outlines, page text spans (text, bounds, font/style), OCR spans, classified reading order, logical sections, and EPUB resources. Process pages incrementally: inspect metadata and outlines; extract positioned PDF text; OCR sparse/scanned pages; classify layout and resolve single-column reading order; join wrapped lines and paragraph continuations across page boundaries; infer chapter breaks from PDF outlines first and validated heading heuristics second; package chapter XHTML, metadata, and an EPUB 3 `nav.xhtml`. Keep source page references in intermediate content for diagnostics. Emit one XHTML per logical chapter/section, not one per PDF page. Preserve the existing page-image conversion as a selectable fidelity mode.

**Durable job management (committed scope):** Integrate PDF conversion into the existing Room-backed converter job manager and its dedicated list/detail surface, following the website converter's visible title/source, status, progress, error, and action patterns. Persist mode/options, source details, stage and page progress, timestamps, status, error, checkpoint key, and result book ID. Offer start, pause, resume, retry, cancel, and removal according to job state; show current stage/page and completed/total pages. Rotation must leave the job and its controls intact. Migrate the current Room schema explicitly without destructive fallback, preserving website jobs and their data.

Each job owns a stable app-private input snapshot. Copy file-picker content after validating/opening it, and snapshot a library PDF under the existing library-operation serialization so deletion or replacement of the original cannot break a paused job. Record source name, size, and content hash; retain the snapshot while the job can resume or retry, and remove it with that job only after no runner owns it. Do not depend on a transient picker URI grant or keep a library lock during conversion.

Checkpoint completed PDF-specific stages and page outputs atomically, keyed by input hash and conversion options. Keep enough page-level text/layout state, including an open paragraph/section continuation, to resume with the same cross-page reflow as an uninterrupted run. Validate checkpoint version and identity before reuse; never reuse website URL/chapter checkpoints. Resume after process death from the last committed page. Packaging is restart-only: rebuild the EPUB from durable extraction/reflow checkpoints, write to a temporary file, validate it, then import atomically. Use a stable job-derived generated-book ID and reconcile an already imported result after a crash so retry/recovery cannot create duplicates. Cancellation stops work and cleans partial packaging; only explicit job removal deletes the owned snapshot and checkpoints, after the runner lease is released.

**Delivery stages:**

1. Freeze a small, licensed fixture set and expected outputs: single-column text with page-spanning paragraphs, explicit PDF outline, repeated headers/footers, scanned pages, mixed text/image pages, two-column pages, tables, and a large document. Run the same fixtures through the pinned Calibre CLI and save version/options plus human-reviewed output notes; compare reading quality, not ZIP bytes.
2. Add bounded, testable extraction and EPUB packaging stages. First release targets single-column digital PDFs: preserve metadata, recover line/paragraph flow, use outlines or heading heuristics for chapters, and generate a usable table of contents. Preserve an explicit page-image option.
3. Add sparse-page OCR and conservative layout classification. If a page is scanned, use OCR text when usable; if reading order is uncertain (including multi-column layouts in this first release), retain that page as an image and make the fallback visible rather than silently interleaving text. Remove repeated headers/footers only when repetition and page-edge evidence are strong.
4. Add the lifecycle and resource guardrails: visible stage/page progress, cancellation between pages, cleanup of partial packaging, atomic library import only after EPUB validation, clear errors for encrypted/unsupported PDFs, and measured limits for page count, temporary disk, output size, bitmap dimensions, elapsed time, and memory on a low-end supported device. Keep at most one rendered page bitmap live; do not retain every OCR bitmap or rendered image.
5. Run user-started work in a progress-notification foreground service, with pause/cancel controls and a shared persisted runner lease. Use bounded WorkManager slices to recover or continue eligible jobs after process death/reboot; yield after committed page checkpoints and reschedule. Pause/cancel must stop both runners and clear automatic-run intent. Document Android background quotas and foreground-service lifecycle limits: WorkManager start times are OS-controlled, and no recovery path promises immediate execution. Roll out text reflow behind a selectable mode or staged flag while keeping image mode available until fixture and device acceptance.

**Acceptance and validation:** Automated fixtures must verify reading order, paragraph joins across pages and resumed checkpoints, preservation of intentional hyphens, header/footer removal without loss of body text, chapter order and working navigation links, valid EPUB metadata and structure, opening in Vibe Reader, and cancellation without a partial library entry. Add explicit Room migration, rotation, process-restart/recovery, pause/resume, retry, cancellation, removal cleanup, stale-lease, and no-duplicate-import tests. Compare text order, paragraph and chapter boundaries, and header removal against the pinned Calibre CLI on PDFs with a text layer. Verify picker and library input snapshots survive source loss, and verify on-device OCR and image fallback against the source pages. Device checks must cover long PDFs, memory and temporary storage, progress, pause/resume, cancellation, recovery, and successful library import. Tables, multi-column reflow, footnotes, mathematical notation, and advanced image placement remain later work.

**Status:** Initial reflow engine and durable PDF jobs are implemented. Kotlin compilation, pure reflow and checkpoint tests, and a SQLite migration smoke check passed. Calibre 9.19.0 was run on a synthetic text fixture. Android-backed tests, device OCR and recovery checks, and broader layout comparisons remain pending.
